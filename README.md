# آماده‌سازی آفلاین جزوه

Python 3.12 و وابستگی‌های requirements.txt لازم‌اند. برای اجرا روی ویندوز روی `run.bat` دوبار کلیک کنید. launcher به‌ترتیب محیط `.venv`، دستور `py -3.12`، سپس `py -3` و `python` را با واردکردن وابستگی‌ها بررسی می‌کند. `rich` اختیاری است؛ نبود آن خروجی متنی ساده می‌دهد. ورودی دستی لازم نیست؛ خلاصه نمایش داده می‌شود و پنجره منتظر کلید می‌ماند.

- `input/`: PDF، Word و PowerPoint خام؛ فقط خواندنی.
- `assets/`: سیلابس، تمپلیت، بوردر و فونت؛ کشف با الگوهای config.yaml.
- `samples/`: مرجع فقط خواندنی؛ `debug/`: شواهد بصری؛ `cache/`: فایل‌های میانی.
- `output/`: PDFهای منتشرشده، `report.html` فارسی و آفلاین، گزارش متنی UTF-8 با BOM، `report.json`، `log.txt` و `log.jsonl`. بایگانی ۲۰ اجرای اخیر در `output/reports/` است.

پیش از هر تغییر، `python tests/run_corpus.py` را اجرا کنید.

محتوا پس از bake و حذف شماره، برداری و یکنواخت میان نوارها کوچک می‌شود؛ پس‌زمینهٔ تمام‌رنگ هم کوچک می‌شود و حاشیهٔ سفید دارد. هر فایل فقط پس از QC منتشر می‌شود. اجرای دوباره همان نام را بازنویسی می‌کند. شکست یک فایل مانع بقیه نیست؛ خروجی قدیمی آن فایل دست‌نخورده می‌ماند و موفقیت اجرای تازه محسوب نمی‌شود. خروجی‌های دارای پیشوند LessonNote_ نادیده گرفته می‌شوند.

```bat
python main.py
python main.py --input tests/data --output tests/results
python main.py --merge "input/physics_thermo_8.pdf" "input/physics_thermo_9.pdf" --namak physics_thermo_8 --output tests/merge_output
```

مسیر خروجی باید در output، cache، debug یا tests پروژه باشد. نام خروجی از نامک کانونی سیلابس و نسخهٔ config ساخته می‌شود. در ادغام، ترتیب فایل‌ها حفظ و فقط یک فرست‌پیج اضافه می‌شود.

«نامک پیدا نشد» یعنی نام فایل با سیلابس تطبیق ندارد؛ «چند منبع» یعنی الگوی assets یکتا نیست؛ «کنترل کیفیت رد شد» یعنی خروجی جدید منتشر نشده و جزئیات هر آزمون در گزارش است. جوهر زیر نوارها باید صفر باشد. تصویر کوچک پایین صفحه ممکن است هشدار شمارهٔ تصویری بدهد؛ تصویر حذف نمی‌شود. فونت یا چهار مقدار نامعتبر، PDF رمزدار و متن بلندِ جا‌نشده نیز خطای همان فایل‌اند.

برای Word/PowerPoint، LibreOffice باید در PATH یا محل معمول Program Files نصب باشد؛ در نبودش پیام «LibreOffice نصب نیست» ثبت می‌شود. تبدیل در cache و بدون تغییر اصل فایل است. نصب LibreOffice خودکار نیست.

## نصب آفلاین

روی سیستم متصل با همان ویندوز، معماری و نسخهٔ پایتون مقصد:

```bat
py -3.12 -m pip download -r requirements.txt --dest wheels
```

پوشه wheels و پروژه را به سیستم مقصد ببرید:

```bat
py -3.12 -m pip install --no-index --find-links wheels -r requirements.txt
```

پوشه wheels در گیت نادیده گرفته می‌شود. اجرای ابزار به شبکه نیاز ندارد.

## دستورها و گزینه‌های رابط

در Windows Terminal و از پوشهٔ پروژه:

```powershell
python main.py doctor
python main.py --dry-run
python main.py --version
.\run.bat --ui fancy --open-report
```

- `doctor`: بررسی نسخه‌ها، منابع، فونت و نوشتن در خروجی؛ نبود `rich` و LibreOffice به‌صورت اختیاری گزارش می‌شود. برای ورودی Office، LibreOffice لازم است.
- `--dry-run`: فقط تطبیق نام فایل با سیلابس و نمایش نامک و رشتهٔ انگلیسی؛ PDF، لاگ یا گزارش تازه نمی‌سازد و QC اجرا نمی‌شود.
- `--ui auto|fancy|compat|plain`: انتخاب رابط؛ `--plain` میان‌بر حالت ساده است. `--no-color` و `NO_COLOR` نیز حالت ساده را فعال می‌کنند.
- `--quiet`: فقط خلاصه و خطاها؛ `--verbose`: نمایش مرحله‌ها و زمان آن‌ها در plain/compat. این دو گزینه با هم استفاده نمی‌شوند.
- `--open-report`: بازکردن گزارش HTML همین اجرا در مرورگر؛ به‌صورت پیش‌فرض مرورگر باز نمی‌شود.
- `--thumbs all`: بندانگشتی برای همهٔ خروجی‌های منتشرشده؛ پیش‌فرض فقط REVIEW است. `--no-thumbs` ساخت بندانگشتی را خاموش می‌کند.

کد خروج: **۰** بدون BLOCKED (شامل REVIEW)، **۱** دست‌کم یک فایل BLOCKED، **۲** خطای راه‌اندازی یا آرگومان/ثبت گزارش، **۱۳۰** توقف با Ctrl+C. در dry-run، کد ۱ یعنی دست‌کم یک نامک تطبیق نیافته است؛ نتیجهٔ MATCH به معنی قبولی PDF در QC نیست.
